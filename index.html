    1. Що таке функція у JavaScript?

    Функція (Function) — це фундаментальний будівельний блок у JavaScript, ізольований блок коду, який приймає вхідні дані (аргументи), виконує алгоритм і може повертати результат.

    У JavaScript функції є громадянами першого класу (First-Class Citizens): вони можуть зберігатися у змінних, передаватися як аргументи іншим функціям і повертатися з інших функцій так само, як числа чи рядки.

    💡 Принцип DRY (Don't Repeat Yourself): Якщо однаковий фрагмент коду зустрічається двічі або більше — його необхідно винести в окрему функцію.

    2. Цілі та завдання функцій

    • Повторне використання (Reusability): один раз написана логіка виконується будь-яку кількість разів із різними вхідними даними.
    • Декомпозиція (Decomposition): розбиття складної монолітної програми на маленькі, зрозумілі, ізольовані підзадачі.
    • Чисті функції (Pure Functions): функції, результат яких залежить виключно від переданих аргументів і не мають побічних ефектів (*Side Effects*). Вони легко тестуються та масштабуються.

    3. Синтаксис оголошення функції

    1. Оголошення функції (Function Declaration)

    function add(a, b) {
  return a + b;
}

    Піднімається (*Hoisting*) на початок своєї області видимості, тому таку функцію можна викликати навіть до рядка її оголошення у коді.

    2. Функціональний вираз (Function Expression)

    const multiply = function(a, b) {
  return a * b;
};

    Функція створюється в момент виконання відповідного виразу та не піднімається у повному обсязі.

    3. Стрілкові функції (Arrow Functions)

    const square = x => x * x; // неявне повернення
const greet = (name, role = 'user') => {
  return `${name} (${role})`;
};
    🔍 Ключові відмінності стрілкових функцій від звичайних:
    • Лексичний this: у стрілкових функцій немає власного this, вони беруть його із зовнішнього оточення на момент створення.
    • Відсутність arguments: замість застарілого псевдомасиву arguments використовуйте сучасний синтаксис ...rest.
    • Не можна викликати через new: стрілкові функції не мають внутрішнього методу [[Construct]] і прототипу prototype, тому не можуть бути конструкторами класів.

    4. Значення функції, що повертається. Ключове слово return

    Оператор return негайно припиняє виконання функції та передає значення у точку виклику.

    • Якщо функція не містить return або викликано порожній return; — функція автоматично повертає undefined.
    • Патерн Early Return (Guard Clauses): перевірка некоректних або граничних умов на початку функції з миттєвим виходом замість глибоких вкладених блоків if/else.

    5. Область видимості змінної (Scope) та Замикання (Closures)

    Типи областей видимості:

    • Глобальна (Global Scope): змінні доступні скрізь у програмі.
    • Функціональна (Function Scope): змінні, створені всередині функції, не доступні ззовні.
    • Блочна (Block Scope): змінні let та const доступні лише всередині фігурних дужок { ... }.

    Замикання (Closure):

    Замикання — це здатність внутрішньої функції запам'ятовувати своє лексичне оточення (змінні батьківської функції) навіть після того, як батьківська функція завершила своє виконання. 

    function createCounter() {
  let count = 0; // приватна змінна
  return function() {
    return ++count;
  };
}
const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2

    6. Практичні приклади та синтез: Функції + Масиви + Цикли + Рядки

    У реальній розробці функції завжди працюють у синергії з масивами, циклами та рядками. Наприклад, трансформація даних замовлень або фільтрація списків: 

    function formatOrderSummary(orders, minTotal = 100) {
  const result = [];
  for (const order of orders) {
    if (order.total >= minTotal) {
      result.push(`Замовлення #${order.id}: ${order.total.toFixed(2)} грн`);
    }
  }
  return result.join('\n');
}

    7. Що таке виняток (Exception) у JavaScript?

    Виняток (Exception) — це нештатна або помилкова ситуація, що виникає під час виконання програми (Runtime) і перериває нормальний потік інструкцій.

    Якщо виняток не перехопити, він «спливає» вгору по стеку викликів (Call Stack) аж до глобального оточення, що призводить до аварійної зупинки скрипта (Crash).

    ⚠️ Помилки компіляції (Parsing) vs Помилки виконання (Runtime):
    Помилки синтаксису (наприклад, незакрита фігурна дужка {) виявляються рушієм JS ще до старту програми — код навіть не почне виконуватися.
    Винятки (наприклад, user.profile.name коли user є null) виникають безпосередньо під час виконання певної операції.

    8. Стандартні типи вбудованих помилок (Standard Error Types)

    У JavaScript усі вбудовані помилки успадковують властивості від базового класу Error. Головні типи:

    • TypeError (Помилка типу): виникає при спробі виконати операцію над несумісним типом (наприклад, викликати не-функцію foo() або прочитати властивість null.name).
    • RangeError (Помилка діапазону): виникає, коли числове значення виходить за допустимі межі (наприклад, new Array(-5) або переповнення стеку рекурсії).
    • ReferenceError (Помилка посилання): звернення до неіснуючої або ще не ініціалізованої змінної (зокрема у «мертвій зоні» TDZ для let/const).
    • SyntaxError (Помилка синтаксису): виникає при спробі інтерпретувати некоректний код, найчастіше під час виконання JSON.parse('{bad json}') або eval().
    • URIError (Помилка URI): некоректне використання функцій кодування/декодування адрес: decodeURIComponent('%').

    9. Конструкція try...catch...finally

    Конструкція try...catch...finally дозволяє безпечно «огорнути» небезпечний блок коду та забезпечити стійкість додатку (Graceful Degradation).

    1. Блок try

    Містить інструкції, які можуть призвести до помилки. Якщо сталася помилка — виконання блоку try негайно припиняється, і керування передається у блок catch.

    2. Блок catch (error)

    Отримує об'єкт винятку. Основні властивості об'єкта помилки:

    • error.name — назва типу помилки (наприклад, "TypeError", "RangeError").
    • error.message — текстовий опис проблеми, переданий у конструктор.
    • error.stack — повний стек викликів функцій із номерами рядків (для дебагу).
    💡 Optional Catch Binding (ES2019): Якщо об'єкт помилки не потрібен, круглі дужки можна опустити: try { ... } catch { return fallback; }.

    3. Блок finally

    Виконується завжди: як при успішному завершенні блоку try, так і після обробки помилки в catch. Навіть якщо всередині try був викликаний return! 

    function loadData(url) {
  let isLoading = true; // встановлюємо індикатор
  try {
    const data = fetchDataSync(url);
    return data;
  } catch (err) {
    console.error('Збій запиту:', err.message);
    return null;
  } finally {
    isLoading = false; // ГАРАНТОВАНО вимикаємо індикатор!
  }
}
    ⚠️ Підводний камінь: Ніколи не пишіть оператори return або throw всередині блоку finally. Вони «перетирають» будь-які значення та скасовують винятки з блоків try та catch!

    4. Синхронність try...catch та асинхронні пастки

    Конструкція try...catch працює виключно синхронно. Якщо помилка трапляється у запланованому асинхронному коді (наприклад, усередині setTimeout, setInterval або слухача подій addEventListener), зовнішній try...catch її не спіймає, бо рушій вже покинув цей блок! 

    // ❌ Помилка НЕ буде спіймана, вкладка може впасти:
try {
  setTimeout(() => {
    throw new Error('Збій в асинхронному таймері');
  }, 100);
} catch (e) {
  console.log('Цей блок ніколи не виконається!');
}

// ✅ Правильно: огортати код усередині самого колбека:
setTimeout(() => {
  try {
    doRiskyAsyncJob();
  } catch (err) {
    console.error('Помилку безпечно перехоплено:', err.message);
  }
}, 100);

    10. Генерація винятків: Ключове слово throw та кастомні класи

    Оператор throw дозволяє генерувати власні винятки у коді (Defensive Programming). 

    function calculateDiscount(price, percent) {
  if (typeof price !== 'number' || price < 0) {
    throw new TypeError('Ціна має бути невідʼємним числом');
  }
  if (percent < 0 || percent > 100) {
    throw new RangeError('Знижка повинна бути в діапазоні від 0 до 100%');
  }
  return price * (1 - percent / 100);
}

    Власні класи помилок (Custom Error Classes)

    Для зручної ідентифікації бізнес-помилок створюють власні класи, успадковані від Error. Розумний базовий клас автоматично підхоплює назву через this.constructor.name: 

    class AppBaseError extends Error {
  constructor(message, options = {}) {
    super(message, options);
    this.name = this.constructor.name; // динамічно встановлює ім'я дочірнього класу
  }
}

class ValidationError extends AppBaseError {
  constructor(message, field) {
    super(message);
    this.field = field;
  }
}

    Обгортання винятків (Exception Wrapping) та властивість cause

    Низькорівневі технічні помилки (збої мережі, синтаксис JSON) не повинні потрапляти безпосередньо в інтерфейс користувача. Їх обгортають у доменні бізнес-помилки: 

    class OrderServiceError extends Error {
  constructor(message, cause) {
    super(message, { cause });
    this.name = 'OrderServiceError';
  }
}

function processPayment(data) {
  try {
    apiClient.charge(data);
  } catch (rawErr) {
    // Зберігаємо першопричину у cause для діагностики:
    throw new OrderServiceError('Не вдалося списати кошти', rawErr);
  }
}

    Патерн повторного викидання (Re-throwing)

    Якщо блок catch отримує помилку, яку він не вміє обробляти — він зобов'язаний прокинути її далі: 

    try {
  processOrder();
} catch (err) {
  if (err instanceof ValidationError) {
    showUserAlert(err.message); // знайома бізнес-помилка
  } else {
    throw err; // невідома критична помилка — прокидаємо нагору!
  }
}

    11. Золоті поради для студентів: Best Practices & Pitfalls

    • ❌ Антипатерн «Мовчазний catch» (Swallowing Errors):
      Ніколи не пишіть catch (err) {} з порожнім тілом. Це маскує критичні баги, робить відстеження помилок неможливим і ламає поведінку всієї системи. Завжди логуйте, повертайте зрозумілий fallback або сповіщайте користувача.
    • 🛡️ Принцип Fail-Fast:
      Валідуйте аргументи на самому початку функції (Guard Clauses). Краще одразу викинути точний TypeError або RangeError, ніж отримати дивний математичний NaN чи зламаний масив десь у глибині 10-го виклику.
    • 🎯 Не використовуйте винятки для звичайного розгалуження коду:
      Створення об'єкта Error і розмотування стеку викликів — ресурсомістка операція. Для штатної перевірки умов використовуйте звичайні if/else.
    • ⚡ Безпечний кортежний патерн [data, error]:
      Замість десятків вкладених блоків try/catch використовуйте функції-обгортки, що повертають кортеж [result, null] або [null, error]. Це робить код чистим, лінійним і передбачуваним.

    12. Глобальне перехоплення помилок та телеметрія

    Що відбувається, якщо помилка все ж вислизнула за межі всіх блоків try...catch? У браузері існує глобальний обробник: 

    window.onerror = function(message, source, lineno, colno, error) {
  // Відправка діагностичного звіту на сервер моніторингу:
  sendTelemetryLog({ message, source, lineno, stack: error?.stack });
  return true; // запобігає виводу стандартної червоної помилки в консоль браузера
};

// Для асинхронних промісів (Promise rejection):
window.addEventListener('unhandledrejection', event => {
  console.warn('Необроблений Promise:', event.reason);
});
    📊 Принцип роботи сервісів моніторингу (Sentry, LogRocket): вони автоматично реєструють ці глобальні слухачі, щоб розробники миттєво дізнавалися про збої у реальних користувачів без необхідності опитувати їх вручну.
